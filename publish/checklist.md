# 发布前检查清单

`npm run publish:check -- --slug=<slug>` 会自动跑机器能数的部分，**打 ✅/❌**。

**默认流程里没有人工审核环节**（2026-11-13 用户明确要求）：机器 ❌ 必须修，
标「⚠️ 人工」的几项降级为**可选抽查**，不作为发布前置条件。
发布前只需要看一屏：

```sh
npm run preview -- --slug=<slug>
```


## A. 论文解读（writing 阶段产出）

| # | 检查 | 机器 |
| --- | --- | --- |
| A1 | `articles/<slug>/article.yaml` 有 `arxiv_id`、`title`、`venue`、`authors`、`status: drafted` | ✅ |
| A2 | 正文含全部 `required_sections`（来自 `publish/config.yaml`） | ✅ |
| A3 | 摘要 `digest` 80–128 字，且 **不等于**正文首段 | ✅ |
| A4 | 每个 `##` 小节至少 2 处加粗；全文每 100 字左右一个加粗落点 | ✅ |
| A5 | 表格 ≥ 3 个，且每个表格都出现在「主要结果 / 深入分析」内 | ✅ |
| A6 | 行间公式全部单行 `$$...$$`（否则渲染错位） | ✅ |
| A7 | 行内公式用 `$...$`，不含 `\mathrm` 以外的不支持宏（KaTeX 严格模式） | ✅ |
| A8 | 数字与论文表格逐项一致（抽查：所有 `x.xx×` 都能在文中表格找到） | ⚠️ 可选抽查 |
| A8b | 每个小数都能在 `facts.json` 找到出处（表内某格，或论文正文某句） | ✅ |
| A8c | 正文写「N 个任务平均」时，LaTeX 表源里真的有 N 个任务列（EAGLE-3 曾按上一篇写成 6 个，实际只有 5 个） | ✅ |
| A9 | 正文插图 ≥ 2 张（架构图 + 主结果图），路径都存在 | ✅ |
| A9b | 每张图/表都有 `图 N ·` / `表 N ·` 编号，正文引用能对上（不是指向论文原文编号） | ✅ |
| A9c | 开头有元信息块（论文 / 作者 / 链接 / 代码 / 模型） | ✅ |
| A9d | **长图没被截断**：所有正文 PNG 的高度不能贴着抓图视口上限（5000px） | ✅ |
| A10 | 有落地信息（代码 / 模型 / 项目页）；论文确实没开源时可忽略 | ✅ |
| A11 | 正文 ≥ 4,000 中文字（目标 5,000–9,000；低于 4,000 视为论证未展开） | ✅ |

## B. 审稿（review 阶段）

| B2 | 无「AI 味」句式：不是…而是…／值得注意的是…／首先其次最后 | ✅ |

## D. 发布（publish 阶段）

| # | 检查 | 机器 |
| --- | --- | --- |
| D1 | 知乎：**刷新后**标题/正文/图片（含图注）/行间公式全部就位，草稿可见 | ✅ `zhihu-verify` |
| D2 | 小红书：正文 ≤ 1000 字、话题 ≥ 3 个（图片顺序仍需人工确认） | ✅ |
| D2b | 小红书：标题 **≤ 20 字**；标题要在**新建时**就写对（事后原地改会被旧快照回写覆盖，只能重建） | ⚠️ 建草稿时校验 |
| D2c | 小红书：正文有 ≥3 处编号/emoji 锚点，单段 ≤140 中文字（详情页不会连成一片；2026-11-14 用户反馈） | ✅ |
| D3 | 公众号：`article.html` 能打开、`publish_method` 与意图一致 | ✅ |
| D4 | 发布闭环后 `article.yaml` 写 `publish_completed: true` + `urls` | ✅ |
| D5 | 知乎 HTML：公式全是 `data-eeimg="2"`、图注在图 `alt` 里、无 `【图N】` 占位 | ✅ |
| D6 | 公众号 HTML：无 `<style>`/`class`、图都有 `data-src`、无字面 `**`、**无 `<ul>/<ol>/<li>`**、**正文无 `<a>`**、链接标签非空、素材已回填 | ✅ |
| D6b | 公众号外链替代：元信息块有二维码（5–9 枚，每枚带短名）；`content_source_url` 指向 `SITE_ORIGIN`（未配则回退 arXiv） | ✅ |
| D6c | 公众号问答是「问题N / 回答N」编号（不是「问：/答：」）；文末有 `wechat_tags` 标签行，≥6 个 | ✅ |
| D7 | 公众号**读回草稿**：列表标签 0、空 `<section>` 0、链接标签齐全（本地 HTML 干净不代表草稿箱干净） | ✅ `publish:platform --to=wechat` |
| D8 | `links.json` 每条都是本篇的真实落地信息（抽错域名很常见：latex 文档页、hf 博客首页） | ⚠️ 人工 |
| D9 | **（可选）** 自己的站点已重建，列表页含本篇链接，线上可访问 | ⚠️ 人工 |
| D10 | 论文原表渲染成 HTML 后**逐格忠实**：宽表（站点）与紧凑表（知乎/公众号）两条路径各查一遍，每个数字和出现次数都要对得上 LaTeX 表源 | ✅ `npm run verify:table` |

### D9 的机器检查怎么跑

本站不含站点构建。如果你有自己的站，它读 `articles/<slug>/`（markdown + yaml + assets）即可；
重建后确认列表页有本篇链接，再打开正文页看公式和图都渲染出来。
`2026-11-12` 漏掉这步的后果：三平台都发了，个人站上却查不到这几篇。


### D1 的机器检查怎么跑

知乎没有内置自动化，这一步要自己核对：**刷新页面后**再读状态——
只在当前 DOM 里核对等于没验证（见
[references/publish-failure-modes.md](../.claude/skills/paper-publish/references/publish-failure-modes.md)）。

它会**强制刷新**页面再读状态——只在当前 DOM 里核对等于没验证（见
[references/publish-failure-modes.md](../.claude/skills/paper-publish/references/publish-failure-modes.md)）。

### D6 排查口诀

| 症状 | 原因 |
| --- | --- |
| 出现字面 `**` | 加粗以标点开头（如 `**「…」**`）；CommonMark 不认 |
| 图片点不开 | 缺 `data-src` |
| 样式全丢 | 用了 `<style>`/`class`，没内联 |
| 草稿是旧版本 | 建过草稿后又重新渲染了 HTML；**重建草稿**，别只重渲染 |
| **一列空圆点** | 用了 `<ul>/<li>`：微信**打开草稿时**会把每个 `<li>` 拆成「空 li + 内容 li」。本地 HTML 是干净的，所以只能靠 D7 读回查。修法是把列表改成 `<section>` + 手写 `•`（`flattenLists()` 已做） |
| **「相关链接」冒号前是空的** | `project` 类链接没有 `repo` 字段，模板回落成空串 |

> **⚠️ 平台会改写你提交的内容。** 本地 HTML 全绿不代表草稿箱里对。
> 公众号必须用 `wechat-publish.mjs` 的读回验证（D7）；知乎必须用 `zhihu-verify.mjs` 强制刷新后再查（D1）。
> 这两步都不能省，也不能用「我看了一下当前页面」代替。
