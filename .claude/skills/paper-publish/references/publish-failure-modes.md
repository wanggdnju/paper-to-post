# 发布失效模式总账（跨平台、跨论文通用）

> 2026-11-09 ~ 11-15，多篇论文、三个平台，踩到的所有坑按**失效类型**归类。
> 不是事故日记，是复查清单。换一篇论文、换一个平台，先对着这份过一遍再动手。
>
> **分工**：本文件只留**平台 / 渲染 / 解析**层面的教训；
> 浏览器自动化的坑（按键被丢弃、光标位置、会话回收）见
> [browser-automation.md](../../../docs/browser-automation.md)。

## 零、三条铁律

### 铁律 1：验收必须在**落盘之后**做

改完编辑器就在当前页面里读 DOM 核对，等于什么都没验证。
Draft.js / 微信编辑器里的 DOM 是**内存态**，和服务器草稿是两回事：
页面看着全对、刷新之后依然是最早那一版，这种情况真实发生过（2026-11-11）。

```sh
# 唯一可信的验收顺序
重新打开同一个草稿 URL   # 强制重新加载
sleep 10
# 再读 blocks / 图片主机 / data-eeimg / figcaption / 空块数
```

**没有"刷新后仍然正确"这一条，不要说「修好了」。**

### 铁律 2：凡是"脚本说成功"的地方，都要问一句「它靠什么判断成功」

这次连续踩到的静默失败，共同点都是**判据写错，但代码不报错**：

| 判据 | 为什么错 | 正确判据 |
| --- | --- | --- |
| `src` 里含 `zhihu` 就算上传成功 | 失败占位图是 `blob:https://zhuanlan.zhihu.com/…`，同样匹配 | `https://pic*.zhihu.com/` + 无 `.Editable-imageUploader` |
| `getSelection().length > 0` 就算选中 | Draft 内部 selection 没跟着变 | 真按键后内容确实变了 |
| `blocks` 增加了就算粘贴成功 | 可能是追加到旧内容后面 | 首块文本 == 预期首段 |
| `data-tex` 数量对了就算公式对 | 可能全是行内的、全跑到文末 | 逐个查 `data-eeimg` 和所在位置 |
| 超时就算失败，重贴 | 图可能几秒后才传完 → 两张一样的图 | 复查已上传张数是否变多 |

**规则：判据要直接对应"用户看到的结果"，不能是它的一个容易满足的近似。**

**推论（2026-11-12 血的教训）：如果平台会改写你提交的内容，判据必须放在「平台读回来之后」。**
本地文件的正确性**证明不了**草稿箱里的正确性——微信打开草稿时会把每个 `<li>` 拆成
「空 li + 内容 li」，我们本地渲染的 HTML 完全干净，用户在草稿箱里看到的是一列空圆点。
连修两次都没修对，因为两次都在改「我们发出去的 HTML」，而改写发生在平台那一侧。
详见 4.14。

### 铁律 3：位置由**标记**决定，不由光标决定

任何"先粘贴 A、再粘贴 B、靠光标顺次落位"的方案都会错位——
编辑器会在自动保存、失焦、focus 归位时把内部 selection 重置到文档开头。
症状是文档变成「中间几段 + 开头 + 结尾」的旋转错乱（2026-11-11 反复复现三次）。

正确做法：正文一次粘完，需要插对象的地方留**唯一标记**（`⟦IMG3⟧`），
再逐个找到标记所在的块、就地替换。顺序天然正确，与光标状态无关。

## 三、平台表示层类

> 「内容对了，但平台的原生语义没对上」。渲染出来的东西和作者想的不一样。

### 3.1 行间公式其实是行内

| 项 | 内容 |
| --- | --- |
| 症状 | 公式左对齐、前面好几个空行 |
| 根因 | 知乎阅读页样式是 `.ztext-math[data-eeimg="1"]{display:inline-block}`、`[data-eeimg="2"]{display:block;text-align:center}`。工具栏「公式」按钮只会产出 `1` |
| 铁律 | **直接写平台的原生节点** `<span class="ztext-math" data-eeimg="2" data-tex="…">`，不走工具栏插卡 |
| 自查 | `[...document.querySelectorAll('[data-tex]')].every(e => e.dataset.eeimg === '2')` |

附带：工具栏插卡流程还要「选中 → Backspace → **Enter×2** → 点公式 → 确认」，
那两次 Enter 每次留一个空段落——这就是「公式前好几个空行」的来源。
2026-11-09 还出过「跳过 Enter → 三张卡全跑到文末」的事故。**这条路整体放弃。**

### 3.2 图注写成了正文

| 项 | 内容 |
| --- | --- |
| 症状 | 图片和表格都没有描述 |
| 根因 | `<img><br>图注` 粘完只是图片下面一段普通段落；知乎的图注在图片块自己的 `figcaption` 里 |
| 铁律 | 图注放 `alt`，灌稿时点注释区 → `.Image-captionInput textarea` → **真按键 Enter** 提交 |
| 自查 | 所有 `figcaption` 都不能是 `is-placeholder` |

注意：直接改 `textarea.value` + 派发 `input` 只更新显示，Draft 的实体数据没改，
切块后会回退成「添加图片注释」。提交必须是真按键。

### 3.3 data URI 图片不再上传

| 项 | 内容 |
| --- | --- |
| 症状 | 8 张图变成同一张「图片导入失败」占位图（URL 哈希相同、`naturalWidth=0`） |
| 根因 | 2026-11-11 起知乎编辑器不再为粘贴 HTML 里的 `data:` 图片触发上传。最小复现：340 字节纯色 PNG 也一样，与体积无关 |
| 铁律 | 图片走**文件粘贴**（`dt.items.add(new File(...))`），等价于从访达复制图片 Cmd+V |
| 自查 | 每张图 `src` 必须是 `pic*.zhihu.com`，不能是 `blob:` |

### 3.4 公众号的几处硬限制

| 限制 | 后果 | 做法 |
| --- | --- | --- |
| 只认白名单标签 | `<figure>/<figcaption>/<style>/class` 被削 | 全部内联 `style`，用 `<section><p><span><img><table>` |
| 不渲染 KaTeX/MathML | 公式变成 TeX 源码 | 公式转 PNG（短式降级 Unicode） |
| 图片必须微信域名 | 相对路径 / `data:` 被丢弃 | 先传素材库换 URL；同时写 `data-src` 才能点开放大 |
| `author` 限 8 字节 | 4 个汉字到顶 | 默认 `Paper`，`bytesSlice()` 兜底 |
| `breaks:true` | `<ul>/<ol>` 被 `<br>` 切断，列表编号跳着走 | `breaks:false`，并剥掉 `<li>` 里的 `<p>` |
| grid / flex | 元信息块挤成一坨 | 逐行渲染成独立 `<p>` 卡片 |
| CommonMark | `**` 后紧跟标点不构成加粗，正文出现字面星号 | 加粗不要以标点开头；中文用「」不写 ASCII 引号 |

## 四、渲染 / 解析类

> markdown → HTML 这一层，最容易写出「看起来对、实际吞内容」的正则。

### 4.1 贪婪正则吞掉整列

| 项 | 内容 |
| --- | --- |
| 症状 | 表格第一列变成 `2 HumanEval`、`2cGSM8K` |
| 根因 | `\\multicolumn\{(\d+)\}\{[^}]*\}\{(.*)\}` 用了贪婪 `.*` |
| 铁律 | 跨嵌套结构一律非贪婪 `[\s\S]*?`，并加单测锁死 |

### 4.2 「句末标点 + 表格行」的切分吞掉表头

| 项 | 内容 |
| --- | --- |
| 症状 | 修复「正文和表格粘在一行」时，表头 `| 模型（T=0）` 整列消失——比不修更糟 |
| 根因 | `^(.*[。！？；】）)])\s*(\|.*\|)$` 里 `）` 也匹配表头里的 `（T=0）` |
| 铁律 | 从**第一个合法的切分点**开始试，逐个 `|` 位置验证左右两侧都成立 |
| 自查 | 有回归测试，断言表头列数不变 |

### 4.3 渲染器静默降级

| 项 | 内容 |
| --- | --- |
| 症状 | 知乎正文里出现「用法：正文一次性粘贴…」和公式清单表格 |
| 根因 | 找不到 `## 正文` 时 `?? source` 兜底，把整份稿子当正文 |
| 铁律 | 契约缺失就**报错退出**，不要兜底 |

同类：行内 `$...$` 原样泄漏（eagle 76 个 `$`）、`【表N】` 不认识被当纯文本、
图表引用指向论文原始编号（图 8 / 表 5）而本篇只有 7 图 4 表。
**这类都要靠 A9b（引用编号一致）之类的机器检查兜住。**

### 4.4 图注只读 `textContent`，全部丢失

| 项 | 内容 |
| --- | --- |
| 症状 | 小红书切图里图片都在，但一张图注都没有 |
| 根因 | `marked` 把 `![图 1 · …](x.png)` 渲染成 `<p><img alt="图 1 · …"></p>`——图注只在 `alt` 里，`element.textContent` 是**空的** |
| 铁律 | 图注取 `textContent \|\| img.alt` |
| 自查 | 切图里每张图下面都要有灰色小字说明 |

### 4.5 分页把图注和图拆开

| 项 | 内容 |
| --- | --- |
| 症状 | 架构图占满一页，图注孤零零落在下一页 |
| 根因 | 分页只处理了「页尾是图注 → 图和图注一起挪走」，没处理「页尾是图、图注被挤到下一页」 |
| 铁律 | 图和图注是**一个不可拆单元**，两种断法都要回退 |
| 自查 | 每张图所在页必须同时包含它的图注 |

### 4.6 切图全是文字，没有图和表

| 项 | 内容 |
| --- | --- |
| 症状 | 10 屏小红书长图全是字，用户反馈「怎么都没有论文的图片和表格」 |
| 根因 | `xhs-article.md` 派生时只挑了纯文字段落；渲染器其实完整支持 `<img>` 和 `<table>`，**问题在源稿内容** |
| 铁律 | `xhs-article.md` 至少 1 张架构图 + 1 张结果图 + 1 个表格 |
| 补充 | **表格不一定要用论文原表**。论文表常是 8–10 列、手机上挤成一团；自己整理成 4 列以内更好读，数字与 `article.md` 逐项一致即可 |
| 自查 | `publish-check` 的 C6：`小红书正文：N 张图、M 个表格`，任一为 0 就报错 |

**2026-11-12 补：派生侧也补了保证。** 上面这条只管「已经写好的稿子有没有图表」，
但 `derive-variants.mjs` 的裁剪逻辑一直在**主动删掉**它们：

- 裁剪优先序是「所有 h2 → 所有保留句 → 按文档顺序补满 20 块」，图和表没有配额，
  被裁的永远是靠后的块——正好是「主要结果」「消融」里的那几张图；
- `ok` 判据只看字数/节数/保留句，图表数为 0 也判通过；
- JSON 解析失败时的兜底只挑 `h2` 和 `para`，img/table **必然**被排除。

现在三处都改了：裁剪时给 `img`/`table` 各锁 1 个名额；`ok` 断言成品里 `imgN≥1 && tableN≥1`；
派生结果里输出 `imgN`/`tableN` 供人核对。

### 4.7 表格和表标题被拆到两页

| 项 | 内容 |
| --- | --- |
| 症状 | 一页底部只有「表 2 · 各方法在六个任务上的加速比」，表格本体在下一页 |
| 根因 | 分页只把「图 + 图注」合并成不可拆单元；`表 N · …` 在 marked 里是普通 `<p>`，和 `<table>` 是两个独立块 |
| 铁律 | 表标题和表格体是一个单元，跟图+图注同等对待 |
| 自查 | 每张表所在页必须同时包含它的标题 |

### 4.8 整体 `scale()` 缩放救不了图片

| 项 | 内容 |
| --- | --- |
| 症状 | 日志说「第 6 屏整体缩放到 0.85」，截图里图片照样越界 35px |
| 根因 | 缩放是 `transform: scale(k)` + `body.style.width = 100/k%`。文字是字号驱动，会被缩小；**图片是 `max-width:100%` 宽度驱动**，容器变宽后图片重新布局成更宽，视觉尺寸不变 |
| 铁律 | 图片超高只能压 `max-height`，不能靠整体 scale |
| 自查 | 缩放后**重新量** `used/avail`，还超就继续处理，别直接截图 |

### 4.9 标题独占一屏

| 项 | 内容 |
| --- | --- |
| 症状 | 第 5 屏只有一行「3. 方法：展开 + 重排」，架构图在第 6 屏 |
| 根因 | 装箱时图太大装不下，标题被先放进了当前页；只做了「标题不能落在页尾」，没做「标题不能独占一页」 |
| 铁律 | 箱子只有一个标题时，把下一块硬拉进来，超高交给缩放兜底 |
| 自查 | 任何一屏都不应只有标题 |

### 4.10 末屏只剩两行字

| 项 | 内容 |
| --- | --- |
| 症状 | 长图最后一屏几乎全白，只有一段话 |
| 根因 | 顺序装填到末尾，最后一块刚好单独成页 |
| 铁律 | 末页内容不足可用高度 35% 时：合并后 < 1.35 倍可用高度就并回上一页；并回去超太多就**从上一页末尾往前借块**，让末页至少半屏 |
| 自查 | 末屏至少占到半屏 |

### 4.11 缩放后页码被顶出画布

| 项 | 内容 |
| --- | --- |
| 症状 | 那一屏没有页码和落款 |
| 根因 | `transform: scale()` 只改视觉，**不改布局占位**；`.page-no` 用 `margin-top:auto` 被推到画布外 |
| 铁律 | 缩放的同时把 `slide-body` 的高度按 `used × k` 压回去，并加 `overflow:hidden` |

### 4.12 封面内容顶到页脚

| 项 | 内容 |
| --- | --- |
| 症状 | 第 4 张数据卡和 `arXiv:xxxx` 页脚叠在一起 |
| 根因 | 封面固定 1080×1440 且 `overflow:hidden`，不量高度就直接截图 |
| 铁律 | 截图前量「内容底边 vs 页脚顶边」，重叠超过 24px 就报错退出；卡片文案要短（值 ≤ 8 字符） |
| 附注 | 长 H1（英文全名）会占三行，用 `article.yaml` 的 `cover.title` 传短标题 |

### 4.13 图注里的行内公式原样漏出

| 项 | 内容 |
| --- | --- |
| 症状 | 图注显示成「输入里的 a^t+1\hat{a}_{t+1}a^t+1 偏离真值」 |
| 根因 | `marked` 把图注放在 `img.alt`，渲染器把它当**纯文本**塞进 `.figcap`，`$...$` 不会被 KaTeX 处理 |
| 铁律 | 图片 alt（也就是图注）里**不要写行内公式**，用文字描述；正文里的公式不受影响 |

### 4.14 平台侧的归一化：**本地 HTML 正常 ≠ 草稿箱里正常**

这一类是 2026-11-12 最难查的一次，核心教训比具体 bug 更重要。

**症状**：用户在公众号草稿箱里看到一列空圆点，每个圆点单独一行、正文另起一行。
同一份 HTML，**没被打开过的草稿是干净的，打开一次就坏了**。

**根因**：归一化发生在**微信那一侧**。微信编辑器在打开草稿时重写结构，把每个 `<li>` 拆成两个：

```html
<!-- 我们提交的 -->
<li style="...">内容…</li>

<!-- 微信打开后存回去的 -->
<li><section><span leaf=""><br></span></section></li>   <!-- 空的，就是那个圆点 -->
<li style="...">内容…</li>
```

服务器上可以直接验证：同一批渲染的草稿，你点开过的有 58 个空 `<li>`，没点开过的 0 个。

**为什么连修两次都没修对**：
1. 第一次以为是 `<li>` 里套 `<p>` → 剥 `<p>`。没用，紧凑列表根本没有 `<p>`。
2. 第二次以为是 `<li>` 内侧有换行 → 剥空白。也没用，微信拆的是标签，不是空白。
3. 两次改的都是**我们生成的 HTML**，而问题出在**别人家的编辑器**。

**真正的解法：绕开会被改写的结构。**

```html
<!-- 不要 <ul>/<li>，改成 section + 自己写的符号 -->
<section style="margin:0 0 10px;padding-left:22px;text-indent:-16px;">• 内容…</section>
```

符号是普通字符，微信没有可拆的列表语义。`render-wechat.mjs` 的 `flattenLists()` 负责转换，
支持嵌套与有序列表。**D6 现在禁止任何 `<ul>/<ol>/<li>` 出现在公众号产物里。**

**通用教训（比这个 bug 本身值钱）**：

> 当一个平台会改写你提交的内容时，**判据必须放在「平台读回来之后」**，
> 不能放在「你发出去之前」。本地文件的正确性证明不了草稿箱里的正确性。

这也是为什么公众号驱动的读回验证要查三件事——它们都是平台侧的产物特征，
本地 HTML 查不出来：

| 检查 | 本地 HTML | 服务器草稿 |
| --- | --- | --- |
| 列表标签数 | 0 ✅ | 打开过 → 58 个空 `<li>` ❌ |
| 空 `<section>` | 0 ✅ | 打开过 → 内容被搬走，留空壳 ❌ |
| 链接标签非空 | 正常 ✅ | 渲染期 bug，两边都错 ❌ |

### 4.15 「相关链接」冒号前是空的

| 项 | 内容 |
| --- | --- |
| 症状 | 最后一段显示成「：https://dflash.z-lab.ai」 |
| 根因 | `links.json` 里 `project` 类链接**没有 `repo` 字段**（只有 `url` + `host`），模板写的是 `l.repo ?? l.label ?? ''`，于是左边什么都没剩 |
| 铁律 | 标签按 `repo → label → 类型默认名（GitHub 仓库 / HuggingFace 模型 / 项目页）→ 主机名` 逐级回落，**永远不许为空** |
| 机器检查 | D6 数 `<p ...>：` 的个数，非 0 报错；公众号驱动读回也查 |

### 4.16 `links.json` 会抽到无关链接

| 项 | 内容 |
| --- | --- |
| 症状 | 「相关链接」里混进 LaTeX 官方文档页、HuggingFace 博客首页 |
| 根因 | `extract-links.mjs` 只看 URL 形状（是不是 github / hf / 项目域名），不看语义。论文的参考文献和排版说明里也会出现这些域名 |
| 实例 | eagle3 抽到 `latex-project.org/help/documentation/encguide.pdf`；eagle2 抽到 `huggingface.co/blog/` |
| 铁律 | **`links.json` 生成后必须人工过一眼**（skill 里早就写了这条，但没被当成硬要求执行）。A10 只数条数，查不出「这条是错的」 |
| 自查 | 每条链接问一句：这真的是这篇论文的落地信息吗？ |

### 4.17 末屏最后一行被裁 / 封面卡片压住页脚

| 项 | 内容 |
| --- | --- |
| 症状 | 小红书最后一屏（`NN / NN`）正文最下面半行字被切掉；封面第 4 张数据卡压住 `arXiv:` 页脚 |
| 实例 | 2026-11-12 EAGLE-3 末屏「调度代码不用动」只露出上半行；dspine 封面重叠 56px、dflash/eagle 各差 18px |
| 根因 1 | 分页用的 `AVAIL` 是**写死的** `520-22-16-34=448`，漏算了 banner 高度；真实可用只有 436px。分页以为装得下，渲染时越界 |
| 根因 2 | 越界兜底先做 `transform: scale(k)`，同时又设 `body.style.height=used×k; overflow:hidden`。**裁剪发生在 transform 之前的布局坐标系**，0→used×(1−k) 那截被直接切掉，0.95 的缩放就吃掉最后一行 |
| 根因 3 | 越界检测只遍历 `img, table`，**纯文字溢出根本不检查**，所以脚本全绿、图上是半行字 |
| 根因 4 | 末页「并回上一页」阈值 1.35 倍太宽松，合并后要缩到 0.84 才装下，整屏字号和前后不一致 |
| 修法 | `AVAIL` 改成**实测**（`520 − 34 − body.top`）；缩放时不再设 `overflow:hidden`（高度按 used×k 压回去即可）；越界检测加「正文底边」；合并阈值收紧到 1.18；封面正文超长先整体缩到 ≥0.85，再不行才报错 |
| 自查 | 渲染日志不该出现「整体缩放到 0.8x」；脚本对 `正文底部越界` 直接 `exitCode=1`；末屏抽看最后一行是否完整 |
| 通用 | 「写死的像素常量」和「实测值」不一致时，永远是实测值对。分页、封面这种固定画布，所有边界都要现量 |

### 4.19 主线表：任务数抄上一篇、切片表漏列、宽表缩成马赛克

2026-11-12 EAGLE-2 / EAGLE-3 同时被用户指出「主实验表格有问题」。拆开是三个独立缺陷：

| 缺陷 | 实例 | 为什么机器检查没拦住 |
| --- | --- | --- |
| **任务数抄错** | EAGLE-3 的表只有 5 个任务列，稿子通篇写「六个任务」——因为上一篇 EAGLE-2 是 6 个（多 Natural Questions） | 4.22 / 5.51 确实是那 5 个任务的均值，所有数字检查都通过；错的只是「几个」这个词 |
| **切片表漏列** | EAGLE-2 §5.1 只列 4 列（MT-bench / HumanEval / GSM8K / Alpaca），「平均」列却是 6 任务均值 | 读者按表加一遍对不上；脚本只查「数字在表里出现过」，不查「表能不能反推均值」 |
| **标签口径错** | EAGLE-2 §5.2 表头写「模型（温度 1）」，填的其实是 **MT-bench 单列** | 数字本身正确，只是标签把「单任务」说成了「模型平均」 |
| **宽表缩成马赛克** | 论文原表是 2600–4800px 的截图，站点 `width:100%` 压到 720px（手机 354px）后字高只剩 5px | 截图看着「有这张图」，但每个数字都认不出 |

修法与防护：

- **A8c（新增机器检查）**：正文里「N 个任务平均」的 N，必须等于 LaTeX 表源里 `\multicolumn{2}{c}{…}`
  的任务列数（排除 Mean/Avg 和 `Temperature=` 分组标题）。引用**别人论文**的句子
  （「EAGLE-3 自己论文报的六任务平均」）要排除，否则误报。
- **切片表要么列全，要么在表下写明「Mean 是全部 N 个任务的均值，不是这几列的平均」**，
  并写进 `publish/writing-spec.md` 的硬规则。
- **站点把论文原表单独处理**：`build-site` 优先把 LaTeX 表源渲染成 **HTML 表格**
  （`scripts/latex-table.mjs`），能自适应宽度、能选中复制、数字永远够大；
  截图保留成「看论文原表」的链接。解析不干净时自动退回截图 + 横向滚动。
  颜色对齐参考：`td.model` 标灰、`tr.sec`（Temperature=0/1）整行浅底。

**HTML 表格解析器的三个坑**（都踩过）：

1. **列定义里有嵌套花括号**：`{c p{1.8cm} @{\hspace{1.2em}} cc ...}`，
   用 `[^}]*` 匹配会漏掉整张表（DFlash 就是这样）。必须按括号配对跳过。
2. **一个 tex 文件里有多张表**：EAGLE 的 source 是整篇论文（8 个 tabular），
   按「表 N 取第 N 个」完全对不上。改成按 `\caption{...}` 与正文图注做关键词打分。
3. **multirow 覆盖行的首列**：LaTeX 有两种写法——`& V13B & ...`（首格留空）
   和直接 `V13B & ...`（少一列）。两种都要让出第一列，否则整行右移、最后一格溢出到表外。
   列数自检也必须把上方生效的 rowspan 算进去，否则每行都报「缺列」。

**2026-11-12 第二轮（用户第二次说「这不还是有问题吗」）**：上面三条修完之后
DFlash / DSpine 仍然全程退回截图。真正的原因是「用正则处理 LaTeX 参数」这件事本身——
花括号嵌套就必然出错。重写成分组读取后，又暴露四个新问题：

| 问题 | 症状 | 修法 |
| --- | --- | --- |
| 横线命令只删了名字 | 表头冒出 `<th>(lr){3-18}</th>` | `\cmidrule(lr){3-18}` 要连可选参数和花括号参数一起吃掉 |
| 表头判定看 `\multirow` | DFlash 第一行就是 `\multirow{2}{Model}`，整张表报「没有识别出表头」 | 改成看内容：数据行以数字为主，表头行不是 |
| 「一格两个数」不认 | DSpine 每格是 `4.25 / 3.96`（温度 0/1），被当成表头 | 数字判定允许 `a / b` |
| **表头 rowspan 遮住占位空格** | `Model` 竖跨 2 行时第 2 行写两个 `&` 占位；HTML 里这两个空 `<th>` 也被输出 → 任务名整体右移两列，`GSM8K` 落在 `MATH-500` 列上 | 输出 `<th>` 时按上方 rowspan 丢弃开头的空占位 |

最后一条特别值得记：**它看起来完全正常**。表头有字、列数自检通过、数字全在——
只是每个任务名错了一列。所以又加了一层 `npm run verify:table`（D10）：
表源里每个小数值和出现次数，必须在渲染结果里原样出现。结构检查守不住语义。

**通用教训**：数字对 ≠ 表格对。「这张表说了什么」属于语义层，需要单独的检查——
数一数列数、数一数行数、看看标签和内容是不是一回事。此外还有一条：
**缩略图/截图的标准是「读者能认出数字」**，不是「图里有这张表」。14 列的表压到
手机宽度只剩 4–5px 字高，等于没有。

### 4.20 表格的**平台适配**：同一张表，三个平台要三种形态

2026-11-12 用户问「你知乎、微信都改了吗」——当时只改了站点，`dist/zhihu` 和
`dist/wechat` 里的主结果表还是截图（知乎 base64 JPEG、微信图床 PNG），
而且微信渲染器还有一条规则**主动删掉**原表后面那张可读的切片表，理由是
「原表已经作为图片插入了」。图片在手机上根本看不清，删掉切片表等于删掉唯一可读的版本。

| 平台 | 可用宽度 | 能横向滚动 | 形态 |
| --- | --- | --- | --- |
| 个人站 | 1240px（可放宽） | 能 | 整张 HTML 表，`width:max-content` |
| 知乎 | ~690px | 不能 | 按任务拆成几张窄表 |
| 公众号 | ~343px（手机） | 不能 | 同上，更窄 |
| 小红书 | 780px 切图 | 不能 | 手写切片表（4–8 列） |

紧凑表的做法（`scripts/lib/paper-tables.mjs`）：
1. 相邻的「Speedup / τ」两列**并成一格**写成 `5.15× / 6.53`（信息不丢，列数减半）；
2. 每 2–3 个任务拆成一张表，每张都重复 Model / Method，**能单独复制**；
3. **不出现 rowspan/colspan**——知乎 Draft.js 粘贴会重排合并单元格，公众号也会削；
4. `Temperature=0/1` 从分节行变成一个普通的「温度」列。

改这条时又踩了两个：
- **守卫只匹配 `https://`**：微信返回的是 `http://mmbiz.qpic.cn/...`，所以「已有上传 URL
  就不许不带 `--upload` 覆盖」的守卫形同虚设，又把产物冲回了占位符；
- **强调标记走错管线**：知乎的 `inline()` 会先 `esc()`，塞 `<b>` 会变成字面量；
  公众号产物本身就是 HTML，反而需要 `**` 被转成标签之后才能渲染。
  现在 `paper-tables` 保留 HTML 标签，由各渲染器决定怎么落地。

**通用规则**：一张表在哪个平台长什么样，由「这个平台能不能横向滚动」决定，
不由「我们手头有什么格式」决定。加新平台时先量宽度，再决定是整表、拆表还是切片。

### 4.21 长图被截断：固定视口 + 多页 PDF（2026-11-12，用户第三次报图）

**症状**：EAGLE-2 方法图底部「Attention mask」只露出半行；EAGLE-3 的 train 图
变成「同一张图出现两遍」，第二页还带着 `Pipeline / Figure 5` 的残页文字。

**根因有两个，叠在一起**：

| 根因 | 说明 |
| --- | --- |
| 视口写死 `1800×2400` | `fitH` 把 PDF 铺满 1800 宽后，竖长页需要 2445px。多出来的 45px 被视口切掉——而「裁白边」只能裁不能补，切掉的内容永远回不来 |
| 没限制页数 | PDF 查看器把多页纵向排列。EAGLE-3 的 `train.pdf` 是 `/Count 2`（LaTeX 多留了一张 Figure 5 残页），视口一高就把第二页也截进来，拼成一张重复的图 |

**判据（当时是怎么确认的）**：PNG 高度落在 `4950–5010`（= `2400 × 200/96`），
说明正好卡在视口下沿；`strings file.pdf | grep -E "/Count|MediaBox"` 能看出页数和页面比例。

**修法**（`scripts/fetch-figures.mjs`）：
- 视口高度按 `2400 → 3600 → 5200` 递进，裁完检查「纸面是否顶到截图下沿」，顶到就换更高重试；
- URL 加 `#page=1`，从源头只渲染第一页；
- 再补一刀：找页与页之间的**查看器背景色**（深灰 `40,40,40`，不是白色）连续带，截到那里为止；
- `publish-check` 新增 **A9d**：所有被引用的 PNG，高度贴着 5000px 就报错。

**顺带修的第三个截断点**：站点 `build-site.mjs` 原来用 `sips -Z 1400`（长边缩到 1400），
竖长图被压成 652px 宽，放进 720px 正文列直接糊掉。改成 `--resampleWidth 1400`，
只约束宽度、高度随比例走。

**通用教训**：

> **凡是「先截图再裁切」的链路，视口/画布本身就是一个容量上限。**
> 裁切只能去掉多余的部分，不能补回被视口切掉的部分——
> 所以必须先确保「要的内容整个在视口内」，再去裁。
> 同理，`object-fit: cover` 也会裁掉超出容器的部分（小红书切图里就有这条规则）；
> `-Z` / 长边缩放会让人误以为「缩了就没事」，其实尺寸比例被改了。


### 4.22 元信息块的链接是死文字（2026-11-14，用户看已发布文章时发现）

| 项 | 内容 |
| --- | --- |
| 现象 | 知乎文章开头的「链接 / 代码 / 架构图」三行全是纯文本。`arXiv:2401.15077 ｜ 论文 PDF` 看着像链接，点不动；后面那些站点链接也是死文字 |
| 根因 | `render-zhihu.mjs` 的 `inline()` 把 `[文字](url)` **主动降级**成纯文字，注释写着「知乎粘贴后由编辑器自己识别链接」——这句是错的。2026-11-14 在知乎自建草稿里实测：粘贴含 `<a href>` 的 HTML，Draft.js **会**保留链接节点（读回来 `querySelectorAll('a')` 有 3 个，href 正确） |
| 修法 | `inline()` 改成保留 `<a href>`；裸 URL（架构图那一行是裸链接，`add-arch-links.mjs` 为了兼容公众号刻意写成裸的）也自动包成 `<a>`。实现上用占位符暂存，避免后续的公式/转义规则二次污染 href |
| 防护 | `publish-check` 的 **D5** 加了一条：元信息块里出现 `https?://` 却没有对应 `<a>`，就报「裸 URL 没做成超链接」 |

**教训**：注释里的「实测」要带日期和判据。这条注释从 2026-11-11 就写着「编辑器会自己识别」，
没有人回查过——而它直接决定了读者能不能点到论文和代码。

### 4.22b 元信息块的链接文字应该是短标题，不是 URL（2026-11-14，用户第二次反馈）

上一版把裸 URL 做成了 `<a>`，链接能点了，但**显示的是整串 https 地址**。元信息块里挤着两个长 URL，很难看。

修法：`add-arch-links.mjs` 改写成 markdown 链接 `[动态版（时间轴…）](url)`，`render-zhihu` 保留 `<a href>` 后，
读者只看到短标题，URL 藏在 href 里。各平台的差异要分开处理：

| 平台 | 处理 |
| --- | --- |
| 知乎 | `<a href>短标题</a>`——已实测 Draft.js 会保留链接节点 |
| H5 / 站点 | marked 直接转 `<a>`；站点另外会把「架构图」这行从元信息块里删掉（顶部有 ▶动态/静态 按钮） |
| 公众号 | **正文外链会被微信去 href**，只剩不可点的文字。所以元信息块里的 `<a>` 要展开成「短标题（URL）」，读者能复制。⚠️ 元信息块是在「去 href」那一步之前摘出来的，必须单独展开，否则短标题后面什么都没有 |
| 小红书 | 正文不支持超链接，只能写裸 URL |

**教训**：同一个「链接」在四个平台的正确形态各不相同。改一处前先把四个渲染器都过一遍，
不要假设「知乎能点」就意味着「处处能点」。

### 4.23 知乎图床域名是 zhimg.com，判据只认 zhihu.com（2026-11-14，最贵的一个坑）

EAGLE-1 这篇重灌了六次，每次都是「图 1 上传失败（timeout）」，四到八张图全丢。

| 项 | 内容 |
| --- | --- |
| 现象 | 每张图都报 `timeout`，重试三轮全失败，最后草稿里一个图都没有（标记还留着） |
| 第一个误判 | 以为是图太大 / 网慢。把轮询从 45 秒加到 160 秒——**没用**，仍然全 timeout |
| 真根因 | 成功判据的正则写的是 `^https?://pic[^/]*\.zhihu\.com/`，而图床上传成功后的真实地址是 **`pic1.zhimg.com` / `picx.zhimg.com`**。判据永远数不到新图，于是每张图都等到超时 |
| 验证 | 手工在草稿里粘一张 1×1 PNG，15 秒后读 `img.src` → `https://pic1.zhimg.com/80/...`，`naturalWidth=800`。图一直在传，只是没人认得它 |
| 影响面 | 同一段代码里三处判据（`UPLOADED`、probe、`countUploaded`）都是这个域名，全部改成 `(?:zhimg|zhihu)\.com` |
| 次生问题 | 因为判 timeout 就重试，重试前 `dropFailedImage()` 删掉「最后一张上传失败的图」——它删不掉已成功的图，结果**同一张图被粘了两次**。EAGLE-1 草稿里一度有 10 张图（应该是 8 张） |

**教训**：这不是「网慢」，是**判据写错**。区别在于：网慢会随时间自愈，判据错会稳定复现。
排查时先手工做一次最小验证（贴一张 1×1 的图，读回 `src`），比调超时参数快得多。

### 4.25 图注要按「有图的那个 figure」定位（2026-11-14）

知乎编辑器里 `figure` 不全是图片：`figure.Editable-styled` 里既有图片，也有空占位
（`contenteditable=false` 的 caption 容器）。回填图注时如果按
`querySelectorAll('figure')[i]` 取第 i 个，会**整体错位**——第 1 个 figure 可能根本没图。
正确写法是先过滤：

```js
[...document.querySelectorAll('figure')].filter(f => f.querySelector('img'))
```

过滤条件的 `src` 同样要收两个域名（见 4.23）。

### 4.26 知乎「文章话题」最多 3 个（2026-11-14）

| 验证「有没有变化」时比较整篇文档 | 按**方面**逐项比较（元信息块 / 编号 / 表格 / 标题），否则恒为"有变化" |

| **改了稿只重跑渲染、不重建草稿** | 草稿是 `draft/add` 那一刻的**快照**；之后重新渲染多少遍都不影响草稿箱。改了稿必须整套重跑 |
| **不带 `--upload` 重跑渲染，把已上传 URL 冲回占位** | `render-wechat` 现在检测到产物里已有 `mmbiz.qpic.cn` 就拒绝覆盖（退出码 2），要覆盖得加 `--force` |
| 同一篇在草稿箱里堆了多份 | 建完新的之后遍历 `draft/batchget`，按标题保留最新一份，删掉其余 |
| **封面参数一个都没传进去** | `publish.mjs` 把 `doc`（`{data, source}`）传给了 `buildRenderArgs(data)`，`data.cover` 恒为 undefined，渲染一直用脚本里的默认值（DFlash 的 `6.08×`/`GSM8K`）。**2026-11-12 审查发现，此前每一篇的封面数字都可能是错的**；已改成传 `doc.data`，且 render-article 缺 `--big/--num/--unit/--vs` 直接报错 |
| **图片 404 全链路静默** | 测量前的图片预载把 `onerror` 也当成加载完成，0 高度的图随后被 `offsetHeight > 0` 过滤掉，产物凭空少一张图。已改成收集失败列表，非空即 `exitCode=1` |
