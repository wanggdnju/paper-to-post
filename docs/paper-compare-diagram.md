# 论文以下的两件事：横向对比 + 机制结构图

解读正文回答「这篇讲了什么」。读者读完往往会立刻追问两个别的问题：

1. **它和那几篇比，到底差在哪？**（不只是「涨了多少」，而是「设计上做了什么不同的选择」）
2. **它数据怎么流动？**（一段文字描述五个模块的先后关系，读三遍还在脑子里打结）

这两件事都由派生产物回答，不写进 `article.md`：

| 产物 | 脚本 | 输入 | 站点位置 |
| --- | --- | --- | --- |
| `compare.json` | `npm run compare` | `facts.json` + `article.md` + `research.md` | 正文之后的「横向对比」 |
| `diagram.json` + PNG | `npm run diagram` | `article.md` 方法章节 | 正文之后的「本站绘制的机制图」 |

**为什么不做进正文**：两者都是生成结果，重跑就会变。写进 `article.md` 等于把生成物固化进手稿，
下次重跑要么覆盖掉人工修过的地方，要么和正文里的旧版本并存——两种都会出错。
站点渲染期插入，正文就永远是模型/人写的那一版。

## 横向对比（compare.mjs）

```sh
npm run compare -- --slug=dspine              # 数字 + 机制，调一次 LLM
npm run compare -- --slug=dspine --no-llm     # 只生成数字对比，零成本
npm run compare -- --slug=dspine --table=tab:main-acceptance   # 指定表
```

输出 `articles/<slug>/compare.json`：`numeric`（数字表）、`baselines`（对比对象）、
`dimensions`（机制维度矩阵）、`takeaways`（判断）、`dropped`（被校验拦下的条目）。

### 数字部分：从 facts.json 拼，不让模型碰

模型手写对比表的失败方式很固定：**数字对，但行列串位**。
`verify:numbers` 只能校验「这个数在论文里出现过」，校验不了「它属于哪一行哪一列」——
而串位恰恰是唯一会毁掉可信度的错误。

所以数字表完全由代码生成，每个格子带自己的 facts ID（渲染成 `title` 属性，悬停可见）：

```
tab:main-acceptance@Qwen3-8B/DSpine (ours):Overall / Avg.
```

选表规则（写死在 `buildNumeric` 里，因为踩过坑）：

- 至少 3 个方法 × 3 个指标列，否则不算「对比」
- **caption 里出现 ablation / hyperparameter / schedule 的表直接跳过**。
  消融表和对比表在结构上一模一样（多行 × 多列），但它比的是自己的变体，不是别人。
  错把消融当「和谁比」，是最丢分的那种错。
- **列名是 `col4`、`col10` 这种占位符的跳过**。那是 facts.mjs 给「表头是裸数字
  （并发数 2/4/8）」的列起的名字，读的人根本不知道 `col4` 是并发几。
- 有「本工作」那一行的表优先排序

### 机制部分：模型抽，但必须能指回原文

「条件化发生在哪一层」这种东西没法从数字推，只能读论文。但让模型自由发挥就会开始编。
所以每条 `baselines` / `dimensions` 都必须附一句 `source`，要求是**逐字复制**原文，
脚本做子串校验，对不上就剔除并记进 `dropped`。

校验前会做归一化：去 markdown 强调符、去空白差异、**保留行内公式的内容**
（`$L$ 层` → `l 层`）。最后一版这个细节很关键——早先版本把 `$...$` 整段删掉，
导致「所有 $L$ 层骨干」和原文「所有 L 层骨干」两边都对不上，正确条目被误杀。

`dropped` 不会静默消失，站点上会显示「本次剔除 N 条」，让人知道模型说了但不被采信的东西。

## 机制结构图（diagram.mjs）

```sh
npm run diagram -- --slug=dspine --gen    # 模型起草 spec，再渲染
npm run diagram -- --slug=dspine          # 只渲染已有 spec（秒级）
npm run diagram -- --slug=dspine --png    # 额外导出 PNG（知乎/公众号用）
```

### 为什么是「声明式 spec + 确定性渲染」，不是让模型直接画 SVG

模型画 SVG 的通病是坐标随手写：框重叠、箭头穿字、线接头错位，而且**每次重跑都不一样**，
没法 diff，没法小改。

这里把「画什么」和「怎么摆」拆开：

```jsonc
{
  "title": "DSpine 机制结构图",
  "columns": [{ "label": "统一传递空间", "note": "预测特征与 token 嵌入同坐标" }],
  "rows": 4,
  "nodes": [{ "id": "z", "col": 1, "row": 2, "label": "预测特征 z", "tone": "accent", "kind": "pill" }],
  "edges": [{ "from": "z", "to": "gate", "label": "接收方特征", "style": "accent" }],
  "groups": [{ "label": "逐层因果注入", "cols": [2, 2], "rows": [0, 3], "tone": "green" }],
  "footer": "一句话总结"
}
```

坐标全由渲染器算。改一条边的标签不用重跑模型，重跑也不会把图改乱。

| 字段 | 说明 |
| --- | --- |
| `columns[].label` / `.note` | 列名 + 副标题，都自动折行，按最长的一列统一起排 |
| `nodes[].col/.row` | 网格坐标，决定位置 |
| `nodes[].kind` | `box`（铺满整列）/ `pill` / `op`（按文字收紧）。三者视觉权重不同，读者才分得清「阶段」和「操作」 |
| `nodes[].tone` | `plain` `accent` `green` `orange` `blue` `ghost`，和站点同一套色 |
| `edges[].style` | 同上 + `dashed` `faint`；箭头颜色跟着变 |
| `groups` | 给若干列框一块底色，标出「这是一个整体」 |

### 排版规则（都是被具体问题逼出来的）

- **跨 2 列以上的线走底部总线**，每条占一条独立车道。贝塞尔斜穿会压掉中间几列的框；
  多条线共用一条总线则三条标签叠在一起，等于没有标注。
- **连线标签做碰撞检测**，撞了就上下让开。几条线汇进同一个框时中点必然重合
  （「残差流」压「前驱特征」）。
- **分组名画在分组框上方**，不画在框里——框里第一行就是节点，写进去必然压字。
  分组名如果和列标题一模一样（模型很爱这么写），就不画，否则两行同样的字叠着。
- **表头起点和网格起点分开算**（`headTop` vs `top`）。两者都相对 `top` 定位过一次，
  结果表头被挤进网格，被分组框压住。
- **导出 PNG 时按 `<svg>` 标签上的尺寸取宽高**。用 `width="(\d+)"` 会先匹配到 `<marker>`
  里的整数，图被裁成一小块。

### 起草提示词里的取舍

模型起草 spec 时明确要求「一张图只讲一条主线、不超过 4 列 5 行、标签 ≤ 10 汉字」。
理由是**结构图的价值在于让人一眼看懂数据怎么走**，塞满细节就退化成论文原图（而原图已经在正文里了）。
渲染器还会校验：边的两端节点必须存在，否则静默丢线——缺线的图看着正常，其实漏了信息。

## 站上的呈现

两个区块都插在正文之后（`build-site.mjs` 的 `paperExtras` + `renderDiagram` + `renderCompare`）。

- 机制图用**虚线强调色边框**，图注第一句是「**本站绘制的机制图**」，末尾一句明说
  「这不是论文原图」。原图是证据，这张是理解，读者不该分不清谁画的。
- 对比表套 `.cmp-scroll` 横向滚动容器，本身**不带 `width:100%` 的挤压**。
  窄屏上 8 个指标列缩到 12px 也塞不进 390px，缩字比滚动更糟。
- 正文里手写的 Markdown 表格也包了一层 `.table-scroll`。这是修一个既存问题：
  `width:100%` 拦不住内容更宽的表格，整个页面横向溢出，移动端连导航都被拖出屏幕。

## 测试清单

跑完这两步，验下面几条（都是实际踩过的）：

```sh
npm run compare -- --slug=<slug> && npm run diagram -- --slug=<slug> --png && npm run site
```

1. `site/papers/<slug>.html` 里同时有 `class="cmp"` 和 `paper-fig owned`
2. 图片用 `naturalWidth` 验，不是看有没有 `<img>` 标签——标签在、图 404 是常态
3. 375/390/1280 三种宽度下 `documentElement.scrollWidth - clientWidth === 0`
4. 控制台零报错、零 4xx
5. `compare.json` 的 `dropped` 为空，或者打开的每一条都**确实**不在原文里

## 已知限制

- **只对论文类内容生效**。项目实战/个人想法没有 `facts.json`，也没有「和谁比」这回事。
- **结构图是「一张图一条主线」**，复杂机制需要拆成多张（spec 里加 `"figure": 2` 这种命名待做）。
- **机制维度的质量取决于正文质量**。正文里没写清的机制差异，模型抽不出来——
  它被要求只用材料里的话。
- **`--gen` 出来必须人看一遍**。spec 是结构，结构错了渲染得再漂亮也是错的。
